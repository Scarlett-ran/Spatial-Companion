# 豹豹 — 证据与决策

[Scout 入口](README.md) · [项目入口](../README.md)

这份文档说明豹豹产品方向的依据：研究中有哪些发现，我们据此做了哪些选择，以及哪些问题仍需探索。研究发现与产品选择分别记录，方便读者理解每项判断的来源。

## 1. 访谈中的主要发现

五位受访者接触的是概念视频和口头介绍，并未实际使用豹豹。访谈记录涵盖他们既有的生活与娱乐经历，以及对豹豹的反应。

### 接受数字技术，不等于接受虚拟伙伴

E 喜欢 VR 游戏，也日常使用 AI，但不愿把虚拟动物当作亲密的情感对象。B 则描述了自己与游戏动物相处、产生感情的经历，并希望熟悉的游戏动物出现在现实空间中。

### 已有感情会影响用户想见谁

A 更在意自己的猫；B 希望见到的是已经在游戏中相处过的动物。他们在意的对象都有共同经历，而豹豹对用户来说是一个新角色。

### 设备成本会影响是否愿意使用

A 不愿为虚拟动物专门购买头显；C 曾因重量、画面体验和重复内容减少头显使用；E 体验过有趣的 VR 游戏，但不愿为同样的体验再次专程前往设备所在地。

### 用户反复选择一种体验，有不同原因

B 因剧情与共同经历反复回到游戏；C 会继续追剧、回看喜欢的演出；D 看重朋友在游戏中的语音、行动与反馈，并指出这不只是陪伴。

对豹豹而言，需要了解用户再次相处时具体期待什么：是想看看熟悉的它、享受互动，还是期待新内容。仅用“需要陪伴”概括，会掩盖这些差别。

### 互动还需要让人看懂

C 认为动作回应能让角色像活物，同时指出缺少触感，希望互动表达清楚。D 则疑惑豹豹为什么在家，以及在豹豹闭眼时为什么能察觉伸手。

## 2. 产品选择与理由

| 产品选择 | 理由 |
|---|---|
| 以 emotional bond 为目标，共处和主动接触都可以成为相处方式 | 我们希望用户逐渐在意豹豹，喜欢与它相处，也可能因它的存在感到安心。主动互动不是每次相处都需要发生的事。 |
| 面向对虚拟伙伴持开放态度的人 | 访谈中，对数字技术的兴趣与对虚拟情感关系的接受并不一致。后者更贴近豹豹希望提供的体验。 |
| 让豹豹与用户生活在同一个真实空间，面向轻便 MR 眼镜 | 用户可以在家里发现它、靠近它、把它抱到身边。轻便的载体有助于减少专门为一次互动佩戴设备的负担。 |
| 保持同一只豹豹的外观和少数习惯 | 给用户逐渐认识它的机会，让前后相遇有所联系。第一版不按相处次数解锁亲密动作。 |
| 不说话，通过动作和共处与用户相处 | 用户不必组织话题或解释心情。心情不好时也沿用平时的行为，不要求豹豹识别情绪或作出特殊安慰动作。 |
| 保留自己的活动节奏，也允许暂时不回应 | 豹豹可以继续睡觉或玩耍，不必围绕每次输入行动。它正在做什么应能从动作中看懂。 |
| 用户启用后无需逐次确认，关闭应用或摘下眼镜结束眼镜体验 | 减少重复进入的操作，同时让用户决定何时相处。用户不回应主动靠近时，豹豹不连续催促。 |
| 不要求照料或关系维护，第一版不提供喂食 | 用户可以自由离开和回来，不会因缺席而受到惩罚，也不需要补做任务。 |
| 生活随时间与当地昼夜推进 | 延续豹豹有自己生活的设定。用户再次看见它时，活动和位置可以变化，不必停留在离开时的状态。 |
| 第一版聚焦一只豹豹的居家生活 | 先把观看、靠近、抱起移动和叫醒等相处方式做清楚，不加入抛球任务、多只宠物和户外使用。 |

具体行为与范围见[体验与原型](03-experience-and-prototype.md)。设备、输入方式和实现方案在体验与技术评估中进一步确定。

## 3. 需要探索的关键问题

### 用户从相处中获得什么？

用户可能觉得有趣、放松、安心，也可能只是喜欢豹豹待在身边。了解哪些时刻让用户愿意与它相处，哪些时刻会觉得被打扰，不预设每个人都需要同一种体验。

### 反复相处能否逐渐形成 emotional bond？

关注用户是否开始认识豹豹的习惯、主动想起它，以及再次见面的原因。用户可能最初因为好奇或可爱而接近它，之后逐渐在意这只豹豹。

### 同处一个真实空间带来了什么？

了解在房间中寻找、靠近和抱起豹豹，对用户有什么意义。如果用户不在意这些体验，先检查空间呈现与交互是否到位；若仍没有带来价值，再重新讨论载体或产品方向。

### 豹豹有自己的节奏，用户是否仍能自在相处？

观察豹豹不回应时，用户如何理解它的行为；用户忽略或离开豹豹时，是否担心伤害它或需要补偿。豹豹可以有自己的活动，但不应让用户承担维系关系的压力。

### 设备和操作能否融入日常？

了解用户在什么场景下愿意佩戴眼镜，以及寻找、抱起、叫醒和再次进入是否方便。结合实际使用，判断这些成本是否妨碍用户与豹豹相处。

## 4. 最小原型需要确认的问题

当前先制作 FWP。以下问题用于后续眼镜原型的准备，不代表已经有设备、三维模型、骨骼或动画资源；技术核查可按需要进行，不能代替用户使用。

| 类别 | 核心问题 |
|---|---|
| 设备与平台 | 哪款现有眼镜最适合制作原型？是否开放所需开发能力，需要配套手机或电脑吗？ |
| 空间呈现 | 能否让豹豹稳定地待在真实地面或家具上，并在小范围内移动？定位、遮挡有哪些限制？ |
| 核心互动 | 能否实现抚摸、抱起、移动、放下和戳醒？如果手势识别不够可靠，原型可用什么方式替代？ |
| 角色与行为 | 利用现有素材，实现睡觉、闲卧、玩耍和主动靠近，还需要哪些美术资源和开发工作？ |
| 时间与状态衔接 | 能否在重新打开时，根据离开时的状态、经过的时间和当地昼夜，更新豹豹的活动与位置，而无需持续后台运行？ |
