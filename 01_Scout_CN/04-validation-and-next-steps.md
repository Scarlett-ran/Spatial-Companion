# 豹豹 — 验证与下一步

[Scout 入口](README.md) · [项目入口](../README.md)

当前状态：FWP 0.1.0 已有本地可运行版本和静态发布包，公开部署和用户试用尚未完成。本文记录已确认顺序、边界、当前交付范围和推进条件；具体试用安排仍待确定。
## 1. 验证目标与工作顺序

**制作 FWP → 用户使用与调整 → 制作眼镜原型 → 空间体验试用。**

探索用户如何理解豹豹的生活与互动、从相处中获得什么、哪里觉得无趣或有压力，并判断下一步应调整什么。用户可以为了乐趣、陪伴、放松或安心使用，不要求统一动机。

Functional Web Prototype（FWP）是有独立访问链接、支持重复使用的网页功能原型。单独使用“原型”时，专指后续眼镜上的最小可实现原型。FWP不能回答真实空间共处的价值或眼镜佩戴成本。

## 2. Functional Web Prototype 的交付状态与后续工作

按[体验与原型](03-experience-and-prototype.md)制作一个版本：简化房间、鼠标或触控、三种生活状态、一个固定玩具、已确认互动及时间衔接，不制作主动靠近对照版。

交付前检查核心行为能正常运行、动作与状态自然衔接、重复输入和页面中断可恢复，并提供可独立访问的版本。自测用于检查实现，不作为用户价值证据。

## 3. 邀请用户使用与获取反馈

邀请对虚拟伙伴持开放态度、希望在居家生活中获得陪伴和乐趣的人使用。用户可以主动互动，也可以安静观看或离开；不要求他们先认同关系设定，也不把喜欢真实动物或拥有XR设备作为前提。

轻量了解：发生了什么、哪些动作看不懂、哪些时刻喜欢或不喜欢、再次打开时想看什么、离开或不回应时是否感到负担。先听具体经历，再解释设计；原话、观察与研究者推断分开，故障或提示也应注明。安排的使用与自发打开分开理解，不用“会用”替代实际使用，也不从没有操作推断情绪。

**待确定：** 人数、时长、周期、反馈渠道与事件记录方案。FWP完成后按实际内容安排，不继承旧研究参数；研究中如使用旧概念视频，应将其反应与FWP使用反馈分开。

## 4. 根据反馈决定下一步

| 实际情况 | 下一步 |
|---|---|
| 核心体验正常运行，经过用户使用并处理主要困惑 | 可以推进眼镜原型。 |
| 动作、状态、操作或时间衔接看不懂 | 先定位并处理主要困惑，区分真实故障与行为表达问题，不用故事解释掩盖问题。 |
| 用户普遍觉得无趣或有压力 | 先判断原因，再决定调整或是否继续；不直接加任务、关系维护或内容系统。 |
| 反馈混合、没有足够使用机会或尚未邀请用户 | 如实保留未知，不把技术完成写成体验成立，也不把缺失反馈直接算作失败。 |

重复相处是否逐渐形成 emotional bond 是持续探索的问题，少量试用不能证明长期关系。反馈整理保留具体例子、反例、限制和此次修改；不汇成亲密度或互动分数。

## 5. 推进眼镜原型与空间试用

在设备与所需能力明确后，制作一块活动地面、一个可放置平面的室内原型，区域预先设置并测试，不跨房间。设备未定，不能由轻便AI眼镜、概念视频或网页效果推定空间能力；模型、动画及必要开发缺口按实际评估确定。

先核查呈现、定位、遮挡、互动与进出体验是否达到可试用状态，再了解“它与我住在同一个真实空间里”有什么意义，以及佩戴与操作是否妨碍相处。

空间体验若没有明显价值，先检查呈现和交互是否到位；仍无价值再讨论载体或产品方向，不自动改成屏幕宠物。设备或资源尚未就绪时，说明等待条件，不为填补等待而无限扩展FWP。
