# Scout — Spatial Companion

**领域：** 软件 / 空间交互  
**阶段：** TRL 1–2｜问题探索  
**目标群体：** Z 世代及之后的年轻用户

## Problem statement

部分年轻人希望获得宠物式陪伴，却难以承担真实宠物持续的照料责任。养宠需要长期投入时间、精力和金钱，也受到租住条件、生活方式与可饲养物种的限制。猫狗需要日常照料，宠物生病可能带来额外开销；海豹等动物尤其不能作为普通家庭养宠的现实选择。

虚拟宠物降低了现实养宠的门槛，但桌面和手机中的二维虚拟宠物仍被限制在屏幕界面内，缺少与用户共享的空间位置、身体尺度和可接近的身体。这里的不足是空间实体感的表达条件受限，并不意味着二维宠物不能带来陪伴；空间呈现能否改善体验仍需比较验证。

本项目因此探索：

> **能否利用空间计算，让一只无需用户承担真实照料责任的虚拟宠物，以具有尺度、位置和身体反馈的方式进入用户空间，从而提供比二维宠物更具实体感的陪伴体验？**

低打扰是这项探索的设计约束，而不是另一个独立问题。宠物应能安静存在，只在用户主动注视、靠近或伸手时作出短暂回应；它不依赖持续对话、频繁操作或强制照料维持价值。

## What is true vs. assumed

| 已知事实 / 已有依据 | 证据边界 |
|---|---|
| 真实宠物需要持续投入时间、精力、金钱和长期责任，并受到居住条件与物种的现实限制。 | 说明现实门槛，不代表已确认目标用户的需求强度或采用意愿。 |
| 桌面和手机中的二维虚拟宠物提供了不依赖真实动物的宠物体验，角色呈现在屏幕界面内。 | 说明候选方案的比较对象，不证明空间宠物优于二维宠物。 |
| 我在体验 Apple Vision Pro 的过程中，感受到虚拟内容出现在现实空间，并通过目光、手部动作和视觉反馈产生了接近“触碰”的感受。 | 是个人体验记录，不能推广为用户普遍感受，也不等于物理触觉。 |

**已定设计：** 角色确定为豹豹，角色选择不再列为待验证假设；年轻用户是当前目标群体，其接受度仍待验证。低打扰是设计约束；方案明确无喂养、无签到、无惩罚、无长期照料义务。空间宠物是回应主问题的候选答案，尚不是已验证方案。

| 核心假设 | 待验证判断 |
|---|---|
| D1 · 设计假设 | 在角色和行为相近时，具有三维尺度、稳定位置和可接近身体的空间呈现，比二维呈现更有实体感。 |
| D2 · 设计假设 | 在没有物理触觉反馈时，视觉与行为反馈仍能形成可信的主观触碰感。 |
| U1 · 用户假设 | 无长期照料义务的空间宠物，通过安静共存与轻量回应仍能带来陪伴价值。 |
| U2 · 用户假设 | Z 世代及之后的年轻用户愿意接受这种空间宠物及其设备使用条件。 |
| T1–T3 · 技术假设 | 空间定位、必要输入与反馈、状态逻辑及异常暂停能够组合成可用体验。平台存在基础能力不等于本项目可行性已获证明。 |

当前 Browser 阶段优先检查 T3 中可由浏览器呈现的规则与交互因果关系是否容易理解，并收集 U1、U2 的早期方向性信号；D2 保留为进入真机后的首要体验验证目标。D1 与 T1–T2 仍保留各自的真机证据要求；U3、U4、T4 后置，详见 [假设地图](./02_假设地图.md)。

## Why now

宠物陪伴需求和虚拟宠物并不是新事物，变化的是实现媒介。我对 Apple Vision Pro 空间呈现与眼手交互的亲身体验，为具有位置、尺度并能回应用户的虚拟宠物提供了概念起点，但 Apple Vision Pro 不是目标产品平台。最终产品面向歌尔自有 VR；具体设备、操作系统、引擎、SDK、输入权限、运行场景与稳定性目前均未确认，必须在获得内部技术信息后重新核查，不能由 Vision Pro 的能力推导歌尔目标平台的可行性。[Apple Vision Pro](https://www.apple.com/newsroom/2024/01/apple-vision-pro-available-in-the-us-on-february-2/)

## Why us

歌尔内部已经存在 XR 设备、技术分享和相关专业人员，使项目能够从真实的空间体验出发，并在概念成熟后进一步交流空间定位、手部追踪和交互反馈的实现条件。这并不代表项目已经获得设备或工程支持，但它提供了比纯粹概念想象更接近真实技术环境的后续验证入口。

## 当前边界

当前完成的是一支 [20 秒概念 Demo](../demo.mp4)，用于表达豹豹安静存在、察觉用户、接受触碰并自然结束互动的设计意图。它不是歌尔目标 VR 平台上的真机原型，不能证明空间定位、手部追踪、跨应用共存或陪伴效果已经成立；这些内容仍属于后续需要验证的假设。

当前尚未开展外部用户研究，也未完成浏览器交互模拟。当前范围只包括确认并执行下一步 Browser-based interaction validation：由 Mentor 先决定 Browser Demo 是否是合适的低成本验证方式；若获得 Go，再依次完成 Demo Scope、Test Plan、Build、User Test 和 Go / Kill / Redirect 决策。XR 真机原型不在当前范围内，只有 Browser 验证出现值得继续的信号并再次获得资源决策后，才进入后续考虑。
