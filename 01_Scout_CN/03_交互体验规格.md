# 探索阶段 03 — 交互体验规格

本文把 [02_产品主张与验证框架](./02_产品主张与验证框架.md) 中“各自生活、偶尔相遇”的关系转为候选行为。规则尚未实现，当前以 Browser 为交互参考，真实空间与输入需另行验证。

## 1. 用少量行为表达自主性

设计原则是 **Less interaction, more meaning per interaction（少量互动，每次都有意义）**。用户进入时，豹豹已经在做某件事；它可能察觉用户，也可能继续活动。用户邀请后可以发生回应或小幅靠近，结束后豹豹自然继续自己的事情。没有互动也是完整路径。

`自主活动 → 可选察觉 → 可选回应／靠近 → 退出互动 → 自主活动`

自主活动与对用户的回应需要分开设计：前者有自身节奏，后者在邀请和反馈之间建立可理解的因果。自主性不等于随机或故障，可理解也不等于每次点击都让角色立即服从。用规则和少量预设变体表达主体感，无需完整 AI 人格或后台生活模拟。

| 行为表达 | 本轮处理方式 |
|---|---|
| 开场已经在活动 | 必须覆盖；从休息或一个非睡眠活动的进行阶段开始，避免每次都等待用户唤醒。 |
| 不始终面向用户 | 必须覆盖无邀请分支；可继续观察环境，用户出现不强制它立即转头。 |
| 看向、靠近与伸手 | 在定义的条件下短暂察觉、轻微回应或接受接触；这些是候选输入意图，不是每次必触发的固定流程。 |
| 用户离开或撤回 | 简短关注后结束，不追赶、不要求告别，回到自身活动。 |
| 玩某个东西、自己换位置或带回物品 | 只是表达自主性的候选示例；当前可用原地观察作为非睡眠活动，不要求移动导航、物品系统或狩猎。 |

注视、靠近和触碰描述体验意图。目标平台的输入、精度与权限仍未知，不预设应用可直接读取目光数据；Browser 代理映射见 07。具体反馈时长与触发阈值需在测试计划中确定，不能把文字中的“轻微”“短暂”当作已经确认的参数。

## 2. 五个体验状态与一个安全状态

| 状态 | 体验目的 | 进入条件 | 允许行为 | 退出方式 |
|---|---|---|---|---|
| 自主活动 | 表达豹豹有自己的生活，无需用户操作。 | 会话开始或互动结束；开场选取已在进行的活动阶段。 | 休息、刚睡醒、观察环境或轻微自娱；当前至少覆盖休息和一个非睡眠变体。 | 可继续活动或短暂察觉；不因启动会话自动朝向用户。 |
| 察觉 | 表达有限感知，不强迫用户回应。 | 用户持续注视或主动靠近；无邀请时，单次会话内首次可靠检测进入接近范围可触发至多一次短暂察觉，也允许不触发。 | 转头、睁眼、轻微抬头或短暂观察。 | 用户继续邀请则进入回应；没有邀请则回到自主活动。 |
| 回应 | 确认用户的有意行为。 | 用户伸手、轻触或继续靠近。 | 观察手部、嗅闻、蹭手或接受短暂抚摸。 | 用户继续邀请时可短暂维持；否则进入退出互动。 |
| 可选靠近 | 提供更明确但不强制的互动时刻。 | 用户明确邀请，且空间与输入条件可靠。 | 小幅调整位置，保持安全距离且不遮挡主要内容。 | 被忽略时停止靠近并进入退出互动。 |
| 退出互动 | 清楚结束一次互动。 | 用户移开视线、撤回手或恢复主要活动。 | 减少动作、移开关注并重新安定。 | 回到自主活动。 |
| 安全暂停 | 避免错误、突兀或不安全的空间行为。 | 追踪丢失、输入不确定、空间不足或应用中断。 | 停止移动与互动；无法可靠维持空间位置时隐藏角色，应用中断时不要求继续显示。 | 环境重新可靠后回到自主活动；否则保持暂停。 |

## 3. 手部动作与豹豹回应

| 用户动作 | 豹豹的预期回应 | 不允许的回应 |
|---|---|---|
| 手缓慢靠近 | 留在原处，用眼睛追踪手，轻微歪头；确认安全后嗅闻一次。 | 主动扑向手、瞬间靠近或连续吸引注意。 |
| 轻触额头或脸颊 | 放松表情，小幅闭眼或轻轻蹭向手指。 | 夸张弹跳、强制进入长时间互动。 |
| 短暂轻柔抚摸 | 保持稳定姿态，以呼吸、表情和细小身体动作回应。 | 抓住用户、阻止手离开或要求重复操作。 |
| 快速伸手或突然靠近 | 轻微后缩或暂停，保持安全距离。 | 攻击、惩罚用户或持续表现负面情绪。 |
| 撤回手 | 停止回应，短暂注视后逐渐回到自主活动。 | 追赶、反复靠近或用声音要求继续。 |

手部接触只代表系统未来可能通过视觉、动画和声音反馈模拟接触，不暗示设备能够提供真实触觉。

## 4. 低打扰规则

1. 安静共存是有效状态，不是等待用户操作的空白状态。
2. 每个会话中，在没有用户邀请的情况下，豹豹最多只能从自主活动进入一次面向用户的察觉，且不能继续升级行为强度；这一限制不约束安静的自发活动。
3. 豹豹不能频繁进入中央视野、遮挡主要内容或重复发出声音。
4. 用户忽略豹豹时，不得出现惩罚、负面情绪、进度损失或更强提醒。
5. 不要求持续手势或持续对话；无照料义务的具体规则见下节。
6. 不持续监听环境，不推断用户情绪，也不读取其他应用内容。

## 5. 无照料义务规则

| 明确约束 | 行为要求 |
|---|---|
| 无喂养 | 不设置饥饿、口渴或必须补充的资源条，不用喂食维持健康、存活或亲近状态。 |
| 无签到 | 不设置每日任务、连续登录奖励或必须回访的周期要求。 |
| 无惩罚 | 忽略、离开或关闭不会引发衰弱、生病、死亡、关系降级、进度损失或内疚式提醒。 |
| 无长期照料义务 | 不安排清洁、医疗、成长养成等必须完成的维护任务；不因离线积累待办，返回时无需补做照料。 |

用户可以随时结束互动、隐藏豹豹或关闭体验，不需要告别操作或承诺下次回来。豹豹的休息与恢复不以用户照料为条件；后续若保存状态，也不得引入离线消耗或照料债务。这些规则规定关系不依靠照料维持；共处与陪伴价值仍按 U1、U1a 验证。

## 6. 自然退出规则

- 用户撤回手、移开视线或恢复主要活动，都视为结束邀请。
- 豹豹应在一次简短反馈后降低动作强度，不再次追问或靠近。
- 退出过程应从回应过渡到安定姿态，避免突然冻结或循环播放告别动作。
- 退出后继续自己的安静活动，位置与尺度保持连续。
- 任何输入或追踪不确定都优先进入安全暂停，而不是猜测用户意图。

## 7. 实现范围与验证衔接

当前用少量活动、状态与反馈表达一次相遇，不加入喂养、饥饿维护、签到、亲密度条、惩罚或照料债务。复杂对话、完整人格、长期成长、完整世界、物品和跨应用系统均不进入本轮；设计禁区与后置候选的区别以 02 为准。

手部表格描述候选回应范围，不要求本轮实现多个接触区域；后续首个真机接触实验从额头一个区域开始。原地观察即可承担非睡眠自主活动，不必增加物品或空间移动。若保留可选靠近，也仅在明确邀请和可靠条件下表达小幅调整。

D3／M1 检查行为是否容易理解，D4／M2 检查初步自主性；低打扰与非互动共处价值分别记录，不能互相替代。指标见 [05_假设地图](./05_假设地图.md)，Browser 范围见 [07_Browser_Demo验证目标](./07_Browser_Demo验证目标.md)，现有作品的覆盖情况见下一篇 [04_概念Demo](./04_概念Demo.md)。
