# 探索阶段 06 — 下一阶段决策

项目分为 Browser 和真机两个推进阶段。Browser 阶段由项目发起人独立完成设计、制作、自测、迭代与材料整理；Demo 较成熟后，才申请设备和外部支持。构建、试测和完善是 Browser 阶段内的工作安排，不是需要外部批准的独立阶段。

## 1. 两个推进阶段

| 阶段 | 推进方式 | 阶段结果 |
|---|---|---|
| Browser 阶段 | 独立完成可运行 Demo，检查行为与异常，按可用时间迭代；有条件时收集体验反馈。 | 形成可稳定演示、规则清楚、限制明确的行为参考，具备对外沟通条件。 |
| 真机阶段 | Browser 成熟后，携 Demo 与具体问题申请设备和必要协作；取得条件后核查平台并制作最小空间原型。 | 获得真实尺度、位置、接近和绕看的证据，再决定后续接触与共处研究。 |

Browser 的范围、节奏与版本取舍由本人决定。外部支持是否获得、以何种形式参与，仅在 Demo 较成熟后的真机申请时确认。

## 2. Browser 怎样算较成熟

| 维度 | 完成依据 |
|---|---|
| 可完整演示 | 两种自主活动及邀请、回应、退出可以完整运行；重新开始后可重复演示。 |
| 行为与异常可靠 | 03 的输入优先级、次数限制、撤回、隐藏、关闭和恢复通过自测，无阻碍核心流程的已知故障。 |
| 表现连贯 | 动作能自然衔接，输入与反馈时序明确；无需临时补操作或口头解释来掩盖故障。 |
| 材料可交接 | 有可运行版本、简短演示、行为规则、已知问题和下一步设备需求，能够说明已完成什么、仍需验证什么。 |
| 证据如实记录 | 自测、个人判断和他人反馈分开；无用户反馈时，D3／M1 等用户体验判断仍记为未验证。 |

满足上述条件意味着可以申请下一阶段支持，不代表用户价值或行为理解已经成立。

## 3. Browser 完成后的决定

| 决定 | 适用情况 | 后续行动 |
|---|---|---|
| 申请真机支持 | Demo 达到成熟度要求，核心剩余问题需要设备。 | 携成果与限定请求对外沟通。 |
| 继续完善 Browser | 核心流程、衔接或异常仍有可定位的问题。 | 由本人选定本次修改点，完成后复查，不持续增加功能。 |
| 调整方向 | 机制难以表达意图，或已有反馈挑战人群与需求假设。 | 调整对应前提，说明已有证据是否仍适用。 |
| 暂缓／停止 | 个人时间或当前条件不足，或继续该机制已无充分理由。 | 分别记录等待条件或停止对象；恢复时重新评估。 |

Browser 已成熟但尚未获得支持时，真机阶段保持待启动，不影响 Browser 成果完成状态。是否继续个人迭代由本人决定，不因等待设备而无限扩展 Browser。

## 4. 真机阶段的申请与启动

对外材料包括：成熟 Demo 与演示视频、行为及输入说明、自测和已有反馈、剩余问题、最小设备与协作请求。已有概念视频见 [04_概念Demo](./04_概念Demo.md)，Browser 工作安排见 [07_Browser_Demo验证目标](./07_Browser_Demo验证目标.md)。

首轮请求聚焦 RQ2：目标设备、运行模式、合理尺度、稳定位置、接近和绕看。接触和跨应用不要求一次具备。设备访问、可用能力、权限、部署方式及必要的工程协作确认后，再制定真机范围、人员分工与时间安排。

每次自检或对外沟通记录日期、版本、已解决与未解决问题、决定及下一步。Browser 阶段按个人可用时间安排；真机阶段的外部投入和协作不提前写成承诺。
