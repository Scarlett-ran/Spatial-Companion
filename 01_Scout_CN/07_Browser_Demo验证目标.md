# 探索阶段 07 — Browser Demo 验证目标

Browser 是当前工作方向，正式定位为 **Interaction Logic Prototype（交互逻辑原型）／Baobao Behaviour & Interaction Reference（豹豹行为与交互参考）**。当前尚未构建或测试；本文定义待执行的工作，范围、样本与阈值需在启动前确定。

## 1. 两个任务，一个主要研究问题

研究任务是检查用户能否理解豹豹为什么做出某个行为，以及输入、状态转换和互动结束是否连贯。核心问题是“你如何理解刚才发生的事”，本轮不以陪伴感评分作为主要通过标准。初步自主性和注意力负担是辅助诊断，概念兴趣与陪伴反馈只提供方向性信号。

工程沟通任务是把体验意图转为具体的行为、输入与输出要求：如果真实设备提供某项能力，Scout 将如何使用它，哪些条件仍需核查。Browser 与现有概念视频组成 Vision + Logic：视频表达预期感觉，原型解释准备怎样运作；分工见 [04_概念Demo](./04_概念Demo.md)。

## 2. 最小体验与交互因果

以 [03_交互体验规格](./03_交互体验规格.md) 为行为依据。至少保留休息和一个非睡眠自主活动，以及有互动、未察觉和没有互动的分支。用户进入时豹豹已在活动，结束后继续自己的事情；无需完成固定的触碰流程才算有效体验。

| 用户意图的代理 | 候选行为 | 重点检查 |
|---|---|---|
| Look：悬停或聚焦 | 条件满足时短暂察觉，也可继续原活动。 | 用户能否理解回应或未回应的原因，而不认为系统随机或失灵。 |
| Approach：模拟接近 | 产生轻微回应，保持自然距离。 | 接近与回应之间是否有可读的时序关系。 |
| Reach：模拟伸手或接触 | 嗅闻、接受接触，或在明确邀请后小幅靠近。 | 接近、接触和回应是否区分清楚；不把点击当作实际手部能力。 |
| Disengage：撤回代理输入 | 简短回应后结束互动，回到自身活动。 | 结束是否自然，用户是否误以为还必须做什么。 |
| 无邀请 | 保持自主活动，不持续面向用户或索取回应。 | 角色是否有自身节奏，以及没有互动时是否产生注意力压力。 |

具体代理方式在 Demo Scope 中选定；鼠标悬停、操作、模拟距离可用少量控制表达，不制作完整导航或复杂生活系统。多角色、多触碰区域、物品系统、复杂对话、AI 人格、跨应用实现与长期成长均不进入本轮；产品原则和范围分类以 02 为准。

## 3. 从 Browser 代理到设备需求

以下是待研发确认的映射，不是目标设备已具备的能力，也不是六项能力必须同时获得的承诺。

| Browser 模拟 | 期望设备能力 | 用于支持的交互 | 待核查或替代方式 |
|---|---|---|---|
| Cursor hover / focus | 眼动或可用的关注输入 | 察觉用户关注，决定是否回应。 | 是否开放眼动及数据粒度；头部朝向、系统焦点或显式确认需标为代理。 |
| Cursor / simulated movement | 头部或身体相对接近信息 | 用户接近时产生轻微回应。 | 可追踪对象、参考坐标、距离精度；不能由头部位姿推定完整身体追踪。 |
| Mouse press / pointer interaction | 手部接近、伸手或接触判定 | 嗅闻、接受触碰、撤回后停止回应。 | 手部数据、精度、遮挡和权限；控制器可作为候选替代，体验证据单独解释。 |
| Simulated depth | 空间距离、环境理解与稳定定位 | 保持尺度、距离和空间关系。 | 坐标、平面、锚定、重新定位及遮挡；模拟深度不证明真实深度感知。 |
| Animation feedback | 实时视觉与行为反馈 | 让身体回应与输入相配合。 | 动画系统、性能和端到端延迟；不假设设备提供物理触觉。 |
| Browser state machine | 目标平台行为运行逻辑 | 自主活动、回应、退出、暂停与恢复。 | 生命周期、中断、运行模式和性能；不由状态保存推导跨应用共存。 |

研发交付采用“能力 X → 交互 Y → 验证问题 Z”的结构，并区分首轮空间存在实验的必要能力与后续接触实验的可选扩展。设备型号、引擎、SDK、权限、部署条件和工程支持均须实际确认。

## 4. 本轮能验证什么，不能验证什么

| Browser 能提供的证据 | 必须保留到对应真实条件的问题 |
|---|---|
| 模拟状态逻辑、行为因果与基础理解度 | 真实空间存在、身体尺度、深度感知与空间接近性 |
| 代理输入下的时序、状态转换、自然退出 | 实际注视行为、真实手部追踪与端到端响应时机 |
| 对少量自主活动的初步理解 | 无物理触觉时的可信主观接触、长期自主性与关系连续性 |
| 对角色概念、低打扰和共处的方向性反馈 | 真实空间共处、跨应用可行性、目标设备运行稳定性与实际采用 |

浏览器上的顺畅运行只证明当前模拟可运行；用户觉得角色可爱或愿意再点一次，不能证明空间、陪伴或设备采用成立。真机访问是取得剩余空间证据的必要条件，但仍需符合目标能力的原型、任务和测试。

## 5. 测试观察项

指标定义统一见 [05_假设地图](./05_假设地图.md)。先自由观察和中性追问，再询问具体感受；需要检查未经提示的行为理解时，应先体验 Browser、后看概念视频，或分别记录观看顺序，避免视频提前解释答案。

| 观察项 | 记录方式 | 与决策的关系 |
|---|---|---|
| 行为与因果理解（M1） | 问“刚才发生了什么，你觉得为什么”；记录解释是否对应实际状态、所需提示及误解分支。 | 本轮主要研究证据。 |
| 状态转换与时序（M1／T3） | 记录触发、反馈、撤回、打断与恢复的顺序，以及用户何时认为太早、太晚或不连贯。 | 区分实现故障与用户理解问题；不外推真机延迟。 |
| 初步自主性（M2） | 观察无操作时的自发描述，问“它在做什么，你怎么判断”；区分自身活动、等待、随机和不响应。 | 支持修改行为表达，不证明已形成持续陪伴。 |
| 自然结束与注意力压力（M1／M7） | 用户停止邀请后，观察是否仍被要求操作、是否反复关注、关闭或感到有责任继续。 | 确认少量行为没有引入额外索取。 |
| 概念与共处反馈（U1／U2a，M5 方向性） | 记录自发重复、保留／关闭及具体理由，态度与实际行为分开。 | 探索线索，不替代主要指标，也不单独作为真机进入门槛。 |

用户选择不互动不是操作失败；忘记关闭不等于主动保留；“我是不是打扰了它”也可能代表负担。无需通过引导用户说出“有自己的生活”来证明自主性。

## 6. 执行与交付要求

1. **确认范围和投入：** 选定活动、分支、代理输入、负责人和工作量上限；不因长期愿景追加功能。
2. **补齐测试计划：** 写清样本与招募条件、任务、时长、观察记录方式、观看顺序及预先确定的通过／修改／停止标准。
3. **构建与检查：** 确保输入、反馈、退出、重新进入及模拟异常可重复运行。
4. **测试与归因：** 收集无引导解释、操作、原话和相反反馈，将实现故障、行为误解和体验评价分开。
5. **交付证据与研发参考：** 提交概念视频和原型、状态与分支表、输入输出映射、时序和恢复说明、观察记录、待确认能力及最小真机资源请求。

当前尚未确定样本数量、数值阈值、精确反馈时长与具体设备权限，不能把本文当作已执行的 Test Plan。阶段完成标准和设备申请逻辑见 [06_下一阶段决策](./06_下一阶段决策.md)。
