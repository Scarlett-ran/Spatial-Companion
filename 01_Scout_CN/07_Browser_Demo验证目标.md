# 探索阶段 07 — Browser Demo 验证目标

本章为 Browser v0.1 执行草案，定位是交互逻辑原型与研发行为参考。行为规则见 [03_交互体验规格](./03_交互体验规格.md)，指标见 [05_假设地图](./05_假设地图.md)，决策见 [06_下一阶段决策](./06_下一阶段决策.md)。
## 1. 本轮制作范围

使用桌面浏览器中的单场景二维角色原型，以现有角色视觉参考制作少量动画，不把真机模型或完整 3D 导航作为前提。开工前核对可用的透明角色图、休息／观察循环、转头、嗅闻和退出衔接；现有视频不视为可直接交互的素材。缺失素材计入制作预算，先完成一组输入与动作的样段检查。

| 项目 | 本轮选择 |
|---|---|
| 活动与反馈 | 休息、原地观察两种开场；短暂察觉、一次嗅闻回应、自然退出。 |
| Look | 开／关模拟关注；按钮只说明操作含义，不显示内部状态或预期答案。 |
| Approach | 切换远／近，模拟用户相对接近；角色本身不移动。 |
| Reach | 单击发出一次伸手邀请，无需持续按住，可直接从自主活动触发。 |
| Disengage | 显式“撤回”，终止邀请并清除关注；仍处于近处时不自动重新触发。 |
| 会话控制 | 隐藏／显示、关闭体验／重新开始；刷新建立新会话。 |
| 研究控制 | 配置开场活动、重置场景、模拟输入失效与恢复、导出事件记录；不展示给参与者。 |

本轮不做真实手部或眼动识别、角色靠近、多接触区域、声音、世界或物品系统。浏览器、窗口尺寸和输入设备固定记录，首轮仅覆盖鼠标操作。

## 2. 构建与自测

| 必测分支 | 检查结果 |
|---|---|
| 无互动／未察觉 | 开场不中断活动；休息时仅 Look 不触发，观察时持续 Look 可触发；全程无操作也是完整路径。 |
| 无邀请的察觉 | Approach 或有效 Look 最多触发一次；反复远近切换、隐藏显示和暂停恢复不重置次数。 |
| 邀请、撤回与再次邀请 | Reach 可直接触发；连续点击不延长或排队；撤回停止回应，退出中新的 Reach 可接续。  |
| 隐藏、关闭与重启 | 用户隐藏后不因恢复自动出现；关闭后须重启；新会话重置输入和计数。 |
| 中断与恢复 | 页面失焦、后台切换及模拟输入失效进入暂停；反复失效不回放旧输入，持续故障保持暂停，恢复后等新输入。 |
| 无操作与输入异常 | 用户没有操作时继续自主活动；只有系统确认输入失效时才进入暂停。 |
| 会话与计数 | 首次加载、刷新或“重新开始”建立新会话并重置察觉次数；隐藏／显示、页面切换和暂停恢复均不重置。 |

多个输入同时发生时依次处理：关闭／隐藏、安全暂停、撤回、Reach、Approach、Look。回应期间关闭 Look 不撤销有效 Reach；撤回会清除 Look 和当前邀请。若撤回时仍处于近处，须先切回远处再接近才可能重新触发察觉，且仍受每会话一次的限制。

隐藏、关闭和安全暂停期间不接受普通交互输入。显示后回自主活动；若系统仍异常则继续暂停。暂停恢复时清空模拟关注和接近条件，不把恢复本身视为一次接近。

## 3. 条件允许时收集体验反馈

先独立完成可稳定运行的版本，再根据可接触的参与者逐次收集反馈；不预设必须完成的样本数量。体验者按 01 的优先人群选择，本人负责邀请、引导和记录，体验参与不等于项目获得研发或人员支持。没有可用参与者时继续自测，用户理解与需求假设保持未验证。

如能安排体验，可采用以下约 25 分钟的流程；它用于发现具体问题，不用于估计总体比例。记录实际人数、活动顺序和提示方式；若后续开展有通过率判断的正式研究，须在开始前另定样本与标准。

| 环节 | 时间建议 | 任务与记录 |
|---|---|---|
| 情境访谈 | 5 分钟 | 展示角色前问最近一次独处情境、实际替代及满足／不足，允许“没有需要”。 |
| 自由体验 | 3 分钟 | 不先看视频、不解释角色规则；允许不互动，记录发现入口与自发理解。 |
| 分支任务 | 10 分钟 | 统一说明按钮只模拟什么动作；分别体验两种活动，先各观察约 45 秒，再尝试关注、接近、伸手、撤回和重新邀请。 |
| 中性回顾 | 5 分钟 | 问发生了什么、为什么、再次操作预计怎样，以及何时想停下、有无压力；回到访谈中的真实情境。 |
| 视频与概念反馈 | 2 分钟 | 最后看视频，另记兴趣与期待，不补计为此前行为理解。 |

如有多名参与者，交替安排休息／观察的先后顺序；每种活动使用新会话。由本人安排关键分支的操作机会，不提前解释预期行为。自由体验、标准操作说明后的理解和额外提示后的表现分别记录，不能用提示后的正确解释补计此前的理解。

主动不互动记为有效选择；分支任务中仍拒绝操作则保留缺失，不逼迫完成。隐藏、暂停等异常以本人自测为主，用户因真实故障受影响的观察注明限制，必要时另行补测。
