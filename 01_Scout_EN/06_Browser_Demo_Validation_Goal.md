# Browser Demo Validation Goal

## Why This Step

Scout has produced an initial concept, but the current evidence is not yet strong enough to justify committing XR engineering resources for Goertek's target VR platform. The proposed next step is a low-cost browser demo that tests the core interaction logic and gathers early user signals. If those basic signals do not hold, the direction should change before XR engineering investment begins.

## What I Want to Validate

1. Whether users can easily understand and complete the core interaction loop: notice Baobao → Baobao responds → pet Baobao → Baobao responds.
2. Whether users understand that their input triggered Baobao’s response, and whether they want to repeat the interaction and use the experience again.
3. Whether users express a willingness to let Baobao remain present with minimal disruption while they do other things, rather than perceiving it as a burden.

In the browser, mouse hover and mouse input serve as proxies for gaze and touch. The demo is intended to provide early directional signals about concept and interaction legibility, not a complete conclusion about companionship value.

- **Redirect:** If technical feasibility should be tested first, or if the validation goal and approach are not aligned, revise the path before writing code.
